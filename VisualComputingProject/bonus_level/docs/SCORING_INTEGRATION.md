# Part Three 舞蹈评分集成说明

统一版保留本地双面板 GUI、YOLO Pose、主舞者跟踪和模块化目录，但评分逻辑以
GitHub `zhangyx-project-upload` 最新 Part Three 为主。

## 1. 空间对齐

只评分 COCO `5:17` 的 12 个身体关节。优先以髋中心为原点，缺失时依次退化为
肩中心或可见身体点中心。尺度取以下可用候选的最大值：

- 肩宽；
- 髋宽；
- `1.35 * torso height`；
- `0.35 * visible body span`。

归一化为：

\[
q_i = \frac{p_i-r}{s}
\]

这消除了画面平移和统一缩放，但不会消除身体侧倾或三维透视变化。

## 2. 单帧姿态分

共同可见关节的 coverage 为：

\[
C = N_{common}/12
\]

手腕和脚踝权重为 1.35，其余身体关节为 1.0。位置相似度使用高斯曲线：

\[
S_{pos,i}=\exp\left[-\frac12(d_i/0.55)^2\right]
\]

八个肘、肩、髋、膝角度使用：

\[
S_{angle,j}=\exp\left[-\frac12(\Delta\theta_j/32^\circ)^2\right]
\]

姿态分：

\[
S_{pose}=(0.35S_{pos}+0.65S_{angle})(0.60+0.40C)
\]

## 3. 运动分与静止抑制

使用约 0.4 秒前后的归一化关节位移。运动相似度由 70% 位移向量一致性和 30%
活动幅度一致性组成：

\[
S_{motion}=0.70S_{vector}+0.30S_{activity}
\]

参考舞者正在运动时：

\[
S_{raw}=0.55S_{pose}+0.45S_{motion}
\]

如果玩家几乎不动，额外乘以 0.45 到 1.0 的 anti-static factor。这样可以阻止
玩家摆出一个大致相似姿势后完全静止仍持续获得高分。

参考动作确实静止时，通过 EMA、两次确认和 `0.07/0.10` 双阈值迟滞进入/退出
`Hold`；Hold 帧显示但不计分，避免把编舞停顿误判成作弊。

## 4. 延迟处理

当前玩家帧只与 `[t-0.8s, t]` 内的参考帧比较，不使用未来参考动作。选择最终分
最高的候选，并报告：

\[
lag=t_{player}-t_{reference}\ge0
\]

热身阶段没有 0.4 秒历史时显示 `Sync`，不计入平均分。每个正式计分事件保存
lag，结算页报告 average、median 和 P90。Median 代表典型反应延迟，P90 表示
较慢动作的尾部延迟；若大量样本贴近 0.8 秒上限，说明窗口可能过小或玩家整体
未同步。

## 5. Grade 与总分

| 相似度 | Grade | 基础积分 |
|---:|---|---:|
| `>= 85` | Perfect | 1000 |
| `>= 70` | Super | 700 |
| `>= 55` | Good | 400 |
| `< 55` | Miss | 0 |

每秒最多记录一次正式事件，避免高 FPS 设备天然得到更多分。连续非 Miss 形成
Combo，附加 `10 * min(combo, 20)`，因此技巧分是主项，连击奖励有上限。

## 6. 已验证的边界

`tests/test_temporal_alignment.py` 覆盖：

- 相同姿态接近 100；
- 错误手腕会被扣分并给出错误关节；
- 延迟搜索不会使用未来参考帧；
- 匹配运动接近满分；
- 参考移动而玩家静止时低于 Good，并显示 `Move!`；
- Hold 需要连续确认并使用迟滞退出；
- 用户历史缓冲不会无限增长。

摄像头、双 GUI 和真实 FPS 仍需在用户电脑本地验证，自动测试不能替代现场 demo。
